# note運用 自動化・収益化・周知戦略

対象アカウント: https://note.com/quiet_alpaca7765k
発信者ペルソナ: 理学療法士(PT)であり、自身も子育て中のパパ。
コンセプト: 「PT目線の医学的根拠に基づいた、パパ・ママ向け子育てお助け情報」

このドキュメントは戦略の全体像、`docs/compliance.md` は法規制・免責の詳細、

## 0. 市場性の検証(2026年時点の調査結果)

本格的に運用を始める前に、実際に勝算があるのかを外部データで確認した。

**ポジティブ要因**
- noteは会員数1,000万人突破、年間流通総額170億円規模まで成長しており、
  2025年11月時点でメンバーシップ売上は前年同月比+81.3%と急成長中。
- note公式による有料記事30万件分析(2025年1〜10月)で、**「育児・教育」は
  急成長中の注目ジャンル**として名指しされている。
- 「PT(理学療法士)× パパ」という掛け合わせのアカウントは検索上ほぼ見当たらず、
  既存の「ママ向け育児アカウント」が飽和気味の中でも明確な差別化になる。
- YMYL(健康・医療)領域は資格保有者による発信がE-E-A-T上有利に働きやすい。

**リスク要因**
- 2025年の出生数は約67〜70万人で10年連続過去最少、合計特殊出生率1.14。
  子育て世帯の絶対数が構造的に縮小し続けている。
- noteで累計100万円以上を売り上げたクリエイターは全体のわずか0.2%。
  「大きく稼ぐ」ではなく「専門性を活かした信頼構築+月数万円規模の副収入」を
  現実的なゴールと位置づけるのが妥当。
- 2026年のX(Twitter)アルゴリズムは「エンゲージメントの質」「関係性スコア」
  「滞在時間」重視に変化しており、テキストのみのスレッドは有効だが
  将来的に画像・動画要素の比重が増す可能性がある。

**結論**: ニッチとしての勝算はあるが、市場全体は縮小基調にある。
「一攫千金」ではなく「専門性ブランディング+堅実な副収入」を目標に設定する。

## 1. 自動化の設計方針(できること・できないこと)

**note.comには投稿を行う公式APIが存在しない。** 非公式のリバースエンジニアリングAPIも
存在するが、認証情報の非公式送信・規約違反・アカウント凍結リスクがあるため、
「ログインして自動投稿する」タイプの自動化はこのリポジトリでは実装しない。

代わりに、**下書き生成〜レビュー〜手動最終投稿** という「半自動化」を設計する。
医療系の発信は特に、PT本人による最終チェック(医学的に不正確な記述がないか、
断定的な診断表現になっていないか)が不可欠なため、人間のレビューをワークフローに
組み込むこと自体がリスク管理になる。

自動化される範囲:

| 工程 | 自動化 | ツール |
|---|---|---|
| ネタ出し・年間コンテンツカレンダー | ◎ 自動生成 | `scripts/generate_calendar.py` |
| 記事の下書き(構成・本文・見出し) | ◎ 自動生成(Claude APIで一次ドラフト) | `scripts/generate_draft.py` |
| SNS横展開用の投稿文(X/Instagram) | ◎ 自動生成 | `scripts/generate_draft.py` |
| 週次の下書きPRの自動作成 | ◎ GitHub Actionsで自動化 | `.github/workflows/weekly-draft.yml` |
| 医学的内容の最終チェック | ✕ 人間(PT本人)が必須 | レビュー担当 |
| noteへの実際の投稿・画像添付・公開 | ✕ 手動(数分で完了する軽作業) | note.comエディタ |
| 有料エリアの設定・メンバーシップ管理 | ✕ 手動(note管理画面) | note.com |

ポイント: 「執筆」というコストの9割(構成を考える、たたき台を書く)を自動化し、
「公開判断」という責任が伴う1割は必ず人間に残す。これにより速度と安全性を両立する。

## 2. コンテンツ戦略

### 2.1 コンテンツの柱(pillars)

`content/topics.yaml` にトピックバンクとして持つ。柱は5つ:

1. **発達・運動の目安**(寝返り・お座り・歩行のマイルストーンと、心配な時の見分け方)
2. **抱っこ・おんぶ・姿勢**(親自身の腰痛・肩こり予防 × 赤子の抱き方)
3. **家庭でできる予防**(転倒予防、O脚/X脚の見方、靴選び)
4. **育児グッズのPT目線レビュー**(抱っこ紐、ベビーカー、バウンサーの身体への影響)
5. **パパ自身のケア**(育児中の腰痛・寝不足による不調、セルフケア)

### 2.2 記事テンプレート(すべてのドラフトが従う構成)

1. フック(親が検索しそうな悩みを1文で)
2. 結論の先出し(PTとして最も伝えたい1点)
3. 医学的根拠に基づく解説(平易な言葉で、専門用語には注釈)
4. 家庭でできる具体的アクション(3〜5個、今日からできるもの)
5. 「病院に行くべきサイン」(該当する場合。受診目安を明記し、断定診断は絶対にしない)
6. まとめ + CTA(フォロー・マガジン登録・メンバーシップ・LINE公式への誘導)
7. 免責文(`content/persona.md` の定型文を使用)

### 2.3 更新頻度

週2本を推奨(火・金など)。note のレコメンドは更新の継続性に好意的に働くため、
「無理なく継続できる頻度」を最優先する。多作より継続。

## 3. 収益化ロードマップ

フォロワー数や実績に応じて段階的に収益源を追加する。焦って有料化すると
初期の信頼構築を阻害するため、フェーズを踏む。

### フェーズ0(〜1ヶ月, 0→100フォロワー): 無料で信頼構築
- 全記事無料。プロフィールに「理学療法士」の資格・実績を明記(E-E-A-T)。
- 記事末に無料の「LINE公式」または「メールマガジン」登録導線を設置し、
  資産化できる自分のリストを育て始める(note外に持ち出せる唯一のチャネル)。

### フェーズ1(1〜3ヶ月, 〜500フォロワー): note単体の収益化を開始
- **有料エリア付き記事**: 無料部分で価値提供し、実践編・チェックリストPDFなどを
  有料部分に(300〜500円)。
- **マガジン(定期購読)**: 週2本の記事をまとめて月額500〜980円程度で提供。
- note pro(ドメイン独自化・アクセス解析強化)は収益が安定してから検討で良い。

### フェーズ2(3〜6ヶ月): メンバーシップ化
- **noteメンバーシップ**: 月額課金の会員コミュニティ。
  - ライトプラン(500円): 会員限定記事、質問箱
  - スタンダード(1,500円): +月1回のQ&Aライブ/コメント返信
- 育児グッズの「PT目線レビュー」記事にアフィリエイト(Amazonアソシエイト等)を
  設置。※広告であることの明示が法律上必須(詳細は `docs/compliance.md`)。

### フェーズ3(6ヶ月〜): 高単価バックエンド
noteの外(LINE公式やメルマガの読者)に対して:
- **電子書籍/PDFガイド**(例:「0〜1歳 転倒予防完全ガイド」買い切り1,000〜3,000円)
- **オンライン個別相談**(30分5,000円〜。ただし「治療」ではなく「一般的な情報提供・
  相談」の枠組みであることを明確にする。医師法・理学療法士法上、業として行う
  「治療」に該当しないよう、内容と表現を要確認)
- **動画講座**(Udemy的な買い切り講座、または note内の販売機能)
- **企業タイアップ**(ベビー用品メーカーからのPR記事。ステマ規制対応必須)

## 4. 周知(集客)戦略

### 4.1 note内の露出
- note公式の特集・企画へのハッシュタグ応募(`#今日の一つ` 等、時期の企画に便乗)
- 同じ育児/医療ジャンルのクリエイターとの相互コメント・スキ回り(初期の関係構築)
- 検索SEO: タイトルに「親が実際に検索する語」を入れる
  (例: 「歩き始め 遅い 理学療法士」「抱っこ 腰痛 対策」)

### 4.2 X(Twitter)での横展開(このリポジトリが自動生成する部分)
1本のnote記事から **X**: 4〜6ポストのスレッド形式ティーザー(結論→根拠→note記事へのリンク)
を生成する。SNSはXのみに絞り、運用の手間を最小化する。

投稿の「初速」がリーチを左右するため、note公開とX投稿はできるだけ同時刻に行う。
`scripts/generate_draft.py` は記事本文と同時にこの文面を生成するため、
公開時にコピー&ペーストするだけで済む。

2026年時点のXアルゴリズムは「エンゲージメントの質(返信・ブックマーク)」
「投稿者との関係性スコア」「滞在時間」を重視する傾向が強まっている。
テキストのみのスレッドは引き続き有効だが、将来的には要点をまとめた
画像1枚や短い縦型動画の併用も検討余地がある(フェーズ2以降の拡張候補)。

### 4.3 コミュニティ・オウンドメディア化
- プロフィール文とすべての記事末に「LINE公式」「マガジン」への導線を統一フォーマットで設置。
- read → follow → LINE登録 → (将来の)商品購入、という導線を最初から設計しておく。

## 5. 運用フロー(週次)

1. (自動) 毎週月曜、GitHub Actionsが次の未使用トピックで下書きを生成し、
   レビュー用PRを作成する。
2. (手動, 5〜10分) PT本人がPRの内容を確認・医学的正確性をチェックし、
   必要なら文章を修正してマージ。
3. (手動, 5分) note.comエディタに本文を貼り付け、見出し画像を設定して公開。
4. (手動, 2分) 生成済みのX文面をXに投稿。
5. (自動) 次週分の下書きが翌週月曜に用意される。

この体制であれば、本人の実作業は週合計20〜30分程度に圧縮できる。

## 7. 想定コスト(Claude API利用料)

`scripts/generate_draft.py` は `claude-opus-5` を使用する
(入力$5 / 出力$25 per 1Mトークン、2026年時点の料金)。1本の生成につき、

- 入力(システムプロンプト+指示文): 概算1,000〜2,000トークン
- 出力(note記事本文 + Xスレッド + 内部の思考トークン): 概算3,000〜7,000トークン

という規模感になる想定で、1本あたり **概算$0.10〜0.25(15〜40円程度)**。
週2本ペースなら月8〜9本で **月$1〜2程度(150〜350円程度)** が目安。

これは文字数からの概算値であり、実測ではない。`generate_draft.py` は
生成のたびに実際のトークン使用量と概算コスト(USD)を標準出力に表示するため、
数回運用すれば実測値で上書きして構わない。想定より大きく上振れする場合は
`output_config.effort` を `high` から `medium` に下げるとコストを抑えられる
(執筆タスクなので品質への影響は小さい見込み)。

Anthropic Consoleでのクレジットチャージは数ドル単位の少額から可能で、
上記の想定コストであれば当面のチャージ分で数ヶ月分は十分にまかなえる規模。
実際の最低チャージ額はConsoleのBilling画面で確認すること(変更される場合がある)。

詳細な法規制・免責文言は `docs/compliance.md` を参照。
